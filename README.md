## 💥 Проблема, яку ми вирішуємо

До цього моменту в нашому додатку будь-яка створена група була статичною:

1. **Відсутність ієрархії та прав:** Усі учасники мали однакові права. Будь-хто міг виконувати будь-які дії, або навпаки — не було інструментів для адміністрування бесіди.
2. **Неможливість розширити чат:** Після створення групи не можна було запросити нових друзів чи колег — доводилося створювати абсолютно новий чат з нуля.
3. **Відсутність керування учасниками:** Неможливо було прибрати небажаних учасників чи призначити модераторів.
4. **Висячі «мертві» чати:** Не було механізму безпечного каскадного видалення бесіди разом з усіма вкладеннями, повідомленнями та реакціями.

Ми впроваджуємо повноцінну систему керування: **Творець (Owner)** 👑, **Адміністратори (Admin)** 🛡️ та **Учасники (Member)** 👤, модальні вікна пошуку та додавання нових людей, бейджі ролей та каскадне очищення даних у Convex.

## 🎯 Мета та задачі завдання

### 1. Модель ролей та прав доступу (Convex Backend)

- **Поле `adminIds` у таблиці бесід:** зберігає список ідентифікаторів користувачів із правами адміністратора.
- **Ідентифікація Творця (`creatorId`):** користувач, який створив чат, автоматично фіксується як власник та отримує статус першого адміністратора.
- **Права доступу (RBAC):**
  - 👑 **Творець (Creator / Owner):** безповоротне видалення групи, надання та зняття прав адміністратора, вилучення будь-яких учасників.
  - 🛡️ **Адміністратор (Admin):** додавання нових людей до групи, вилучення звичайних учасників (не може вилучити творця чи іншого адміна).
  - 👤 **Учасник (Member):** читання, листування, реакції, добровільний вихід із групи («Покинути чат»).

### 2. Мутації бекенду Convex (`convex/conversations.ts`)

- **`addParticipantsToConversation`:** перевірка прав, фільтрація дублікатів (не додавати тих, хто вже в чаті), збереження нових учасників та створення системного сповіщення.
- **`updateParticipantRole`:** надання або зняття прав адміна (доступно **виключно** Творцю).
- **`removeParticipant`:** вилучення учасника (kick) або вихід за власним бажанням (leave).
- **`deleteConversation`:** каскадне видалення бесіди (видалення всіх реакцій `messageReactions`, повідомлень `messages` та самої розмови). Для груп видаляти дозволено лише Творцю.

### 3. Системні службові повідомлення (`isSystem: true`)

- Додавання опціонального поля `isSystem: v.optional(v.boolean())` до таблиці `messages`.
- Оновлення компонента `MessageBubble`: якщо `isSystem === true`, повідомлення рендериться нейтральною заокругленою пігулкою сірого кольору по центру екрана (як у Telegram/WhatsApp) без аватарки, стрілочок, часу та реакцій.

### 4. Модальне вікно додавання учасників (`components/AddMembersModal.tsx`)

- Пошук користувачів через `api.users.searchUsers` із фільтрацією за нікнеймом/іменем.
- Автоматичне приховування тих користувачів, які вже є учасниками поточної бесіди.
- Зручний мульти-вибір чекбоксами та кнопка «Додати (N)».

### 5. Модальне вікно деталей групи (`components/GroupInfoModal.tsx`)

- Відкривається при кліку на назву/хедер чату або іконку інформації `ℹ️`.
- Відображення назви групи, кількості людей та інформації про автора чату.
- Список усіх учасників із бейджами ролей:
  - 👑 `Власник` (золотий бейдж)
  - 🛡️ `Адмін` (акцентний бейдж)
  - `Учасник` (нейтральний сірий)
- Кнопки швидких дій для Творця (призначити адміном / зняти адміна / вилучити).
- Кнопка «Покинути групу» (для звичайних учасників) та «Видалити групу для всіх» (для Творця з підтвердженням).

### 6. Швидке керування у списку чатів (`app/messages/index.tsx`)

- Довге натискання (`onLongPress`) на чат відкриває меню вибору:
  - Для 1-on-1: «Видалити діалог».
  - Для групового чату: «Видалити групу для всіх» (якщо творець) або «Покинути групу» (якщо учасник).

## 📁 Очікувана структура файлів

```text
prostir/ (або modern-chat/)
├── app/
│   └── messages/
│       ├── [id].tsx                    # Екран чату (клікабельний хедер, GroupInfoModal)
│       └── index.tsx                   # Список чатів (onLongPress для швидкого видалення)
├── components/
│   ├── MessageBubble.tsx               # Оновлено: рендеринг системних повідомлень по центру
│   ├── AddMembersModal.tsx             # НОВИЙ: модалка пошуку та додавання учасників
│   └── GroupInfoModal.tsx              # НОВИЙ: деталі групи, бейджі ролей, керування учасниками
└── convex/
    ├── schema.ts                       # adminIds у conversations, isSystem у messages
    ├── conversations.ts                # Мутації додавання, зміни ролей, вилучення, видалення
    └── messages.ts                     # Підтримка isSystem у запитах повідомлень
```

## 🧪 Чекліст для самоперевірки

- [ ] При створенні групи творець автоматично зберігається в `creatorId` та потрапляє в `adminIds`.
- [ ] У стрічці нового чату з'являється системне повідомлення: _«🎉 Груповий чат створено»_.
- [ ] При натисканні на хедер чату відкривається `GroupInfoModal` з переліком учасників та їхніх ролей.
- [ ] Кнопка «+ Додати нових учасників» доступна лише творцю та адміністраторам.
- [ ] У вікні додавання відображаються тільки ті користувачі, яких ще немає в цій групі.
- [ ] Творець може натиснути на щит біля учасника, щоб надати або забрати права адміністратора.
- [ ] Після зміни ролі, додавання чи вилучення в стрічці з'являється відповідне системне повідомлення.
- [ ] Звичайний учасник бачить кнопку «Покинути групу», а Творець — «Видалити групу для всіх».
- [ ] При видаленні чату з бази видаляються сама бесіда, всі повідомлення та всі емодзі-реакції.
- [ ] Команда `npx tsc --noEmit` проходить без жодних помилок компіляції.
