## 💥 Проблема, яку ми вирішуємо

У поточній реалізації додаток завантажує **всі повідомлення кімнати одночасно** за допомогою методу `.collect()`, а екран чату використовує стандартний `FlatList` із викликом `scrollToEnd({ animated: false })`:
1. **Зависання при відкритті:** Якщо в кімнаті накопичується 500–2000+ повідомлень, відкриття екрана чату займає від 3 до 7 секунд, під час яких інтерфейс повністю зависає (блокування JS-потоку).
2. **Вильоти через нестачу пам'яті (Out-Of-Memory / OOM Crash):** Мобільний пристрій виділяє обмежений пул оперативної пам'яті. Рендеринг тисяч важких компонентів зі свайп-жестами та картинками спричиняє раптове падіння додатка.
3. **Неприємні «стрибки скролу» (Scroll Jumping):** При спробі підвантажити старі повідомлення у звичайному списку поточна позиція читання користувача зміщується.
4. **Зайві перерендери:** Кожне нове надіслане повідомлення або кожен символ, введений в інпуті, змушував перемальовуватися всі сотні повідомлень на екрані!

Ми оптимізуємо архітектуру за стандартами **Telegram, Discord та WhatsApp**: перейдемо на **курсорну серверну пагінацію Convex**, впровадимо нативний інвертований список **`Inverted FlatList`** та проведемо мемоїзацію рендерингу повідомлень за допомогою **`React.memo`** та **`useCallback`**.

## 🎯 Мета завдання

1. **Серверна пагінація у Convex (`convex/messages.ts`):**
   - Створити функцію `getPaginatedMessages` із валідатором `paginationOptsValidator`.
   - Налаштувати сортування `.order("desc")` за індексом `"by_chat_room"`, щоб перша сторінка містила найновіші повідомлення (для інвертованого списку).
   - Створити допоміжну функцію `seedTestMessages` для швидкої генерації 50+ повідомлень під час тестування пагінації.

2. **Інвертований список у клієнті (`app/chat/[id].tsx`):**
   - Підключити хук `usePaginatedQuery(api.messages.getPaginatedMessages, { chatRoomId }, { initialNumItems: 25 })`.
   - Увімкнути властивість `inverted={true}` у `FlatList`.
   - Назавжди позбутися повільного хаку `onContentSizeChange` та викликів `scrollToEnd()`.
   - Реалізувати плавне довантаження старішої історії при скролі вгору (`onEndReached` + `loadMore(20)`).
   - Відображати верхній індикатор завантаження старіших повідомлень (`ListFooterComponent`).
   - Коректно обробити стан початкового завантаження (`status === "LoadingFirstPage"`) та стан порожнього чату.

3. **Оптимізація продуктивності FlatList та рендерингу бульбашок:**
   - Огорнути компонент `SwipeableMessageItem` у `React.memo`, запобігаючи зайвим перемальовуванням при введенні тексту в інпут або отриманні нових реплік.
   - Стабілізувати функції зворотного виклику (`handleStartReply`, `handleMessageLongPress`, `setFullscreenImage`, тощо) через `useCallback`.
   - Налаштувати параметри віртуалізації `FlatList`: `windowSize={10}`, `maxToRenderPerBatch={10}`, `initialNumToRender={15}`, `removeClippedSubviews={Platform.OS === "android"}`.

4. **Адаптація інтерфейсу чату до інвертованого режиму:**
   - Розмістити індикатор друку `TypingDots` над полем вводу тексту, щоб він не конфліктував із новим порядком списку.
   - Переконатися, що панель цитування `ReplyPreviewBar` та прев'ю зображень працюють стабільно та без затримок.

## 🌟 Бонусні завдання (За бажанням, для додаткових балів)

1. **Кнопка швидкого повернення до найновіших повідомлень («Scroll to Bottom FAB»):**
   - Коли користувач проскролив чат вгору більше ніж на 500 пікселів, показуйте внизу праворуч плаваючу круглу кнопку зі стрілкою вниз `arrow-down`.
   - При натисканні на кнопку плавно прокручуйте список до найновішого повідомлення (`flatListRef.current?.scrollToOffset({ offset: 0, animated: true })`).
   - Якщо під час перегляду старої історії надійшло нове повідомлення, показуйте на кнопці бейдж із червоною крапкою або лічильником нових реплік.

2. **Оптимізація кешування зображень через `expo-image`:**
   - Замініть стандартний `<Image>` у бульбашках повідомлень на `Image` з бібліотеки `expo-image`.
   - Налаштуйте дискове кешування (`cachePolicy="disk"` або `priority="high"`), щоб при скролі важких фотоповідомлень картинки не перезавантажувалися повторно з мережі.

## 💡 Поради щодо тестування

1. **Як протестувати пагінацію, якщо в кімнаті мало повідомлень?**
   - Скористайтеся мутацією `seedTestMessages` із розробленої інструкції або викличте її з панелі Convex Dashboard:
     ```json
     { "chatRoomId": "id_вашої_кімнати", "count": 50 }
     ```
   - За лічені секунди у вашій кімнаті з'явиться 50 реалістичних повідомлень!
2. **Перевірка Inverted-режиму:**
   - Відкрийте чат. Найперше, що ви маєте побачити — найновіші повідомлення внизу екрана.
   - Почніть скролити вгору. Коли ви наближаєтеся до вершини екрана, повинен з'являтися невеликий спінер, після чого над старими повідомленнями плавно з'являється попередня порція без будь-яких ривків екрана.
3. **Перевірка відсутності зайвих рендерів:**
   - Додайте у `SwipeableMessageItem.tsx` рядок `console.log("Render message:", item._id);`.
   - Введіть довгий текст в інпут. У консолі **не повинно бути жодного повідомлення** про рендеринг елементів списку! Це підтверджує, що `React.memo` та `useCallback` працюють бездоганно.
