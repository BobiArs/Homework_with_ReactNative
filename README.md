## 💥 Проблема, яку ми вирішуємо

До цього моменту всі оновлення в нашому месенджері відбувалися виключно через активне WebSocket-з'єднання з базою даних **Convex**:

1. **«Німий» додаток у фоні:** Щойно користувач згортає месенджер або блокує екран смартфона, операційна система Android чи iOS призупиняє виконання JavaScript-потоку та розриває WebSocket-з'єднання. Користувач не знає про вхідні повідомлення, доки сам повторно не запустить додаток.
2. **Відсутність Deep Linking (прямих переходів):** Навіть якщо користувач відкриває додаток самостійно, йому потрібно вручну шукати серед списку бесід потрібну кімнату. Системний пуш повинен містити метадані (`chatRoomId` / `conversationId`) і при тапі миттєво вести безпосередньо у відповідний діалог.
3. **Обмеження Expo Go:** Нативна доставка віддалених пуш-сповіщень через **Firebase Cloud Messaging (FCM v1)** на Android 13+ вимагає справжнього системного дозволу `POST_NOTIFICATIONS`, реєстрації Android Notification Channel та нативної збірки (Development Client або Standalone APK).
4. **Специфіка групових чатів:** У приватних діалогах сповіщення отримує один співрозмовник, а в групових бесідах сповіщення повинні відправлятися **пакетно (Batch)** усім іншим учасникам кімнати (окрім самого відправника), із зазначенням назви групи та імені автора.

Ми будуємо повноцінну інженерну архітектуру: налаштовуємо **Firebase Cloud Messaging (FCM v1)**, з'єднуємо **EAS Credentials** із Google Service Account, реалізуємо чергу відправки у **Convex Actions** та створюємо реактивний клієнтський хук **`usePushNotifications`** із підтримкою гарячого та холодного старту!

## 🏗️ Архітектура доставки Push-сповіщень

```
[Користувач А надсилає повідомлення] (Текст, Фото, Голосове, Відеокружечок)
                 │
                 ▼
      [Convex Mutation: sendMessage]
                 │
                 ├─► Запис повідомлення в таблицю messages
                 ├─► Оновлення lastMessage та lastMessageAt у chatRooms
                 │
                 ▼ (ctx.scheduler.runAfter(0, internal.pushNotifications.send...))
      [Convex Internal Action] (sendPushNotification / sendPushNotificationsBatch)
                 │
                 ▼ (HTTP POST JSON)
        [Expo Push Service] (https://exp.host/--/api/v2/push/send)
                 │
                 ▼ (FCM V1 API з Google Service Account)
        [Firebase Cloud Messaging]
                 │
                 ▼
        [Смартфон Користувача Б]
                 │
                 ├─► Якщо додаток відкритий (Foreground):
                 │   спливає внутрішньосистемний банер зі звуком (setNotificationHandler)
                 │
                 ├─► Якщо додаток згорнутий або закритий (Background / Killed):
                 │   системна шторка показує Push-сповіщення
                 │
                 ▼ (Тап по сповіщенню ➔ Deep Linking)
    [Хук usePushNotifications] ──► router.push('/chat/[id]')
```

## 🎯 Мета та задачі завдання

### 1. Нативна конфігурація та дозволи (`app.config.ts`, `google-services.json`)

- Встановлення нативних бібліотек `expo-notifications` та `expo-constants`.
- Налаштування плагіна `expo-notifications` у `app.config.ts` (іконка сповіщень, колір акценту, канал за замовчуванням `defaultChannel: "default"`).
- Додавання дозволів у секцію `android.permissions`:
  - `"android.permission.POST_NOTIFICATIONS"` (обов'язково для Android 13+ / API 33).
  - `"android.permission.VIBRATE"`.
- Підключення `googleServicesFile: "./google-services.json"` у конфігурації платформи Android.
- Встановлення дійсного `extra.eas.projectId` для коректної генерації токена `ExponentPushToken`.

### 2. Налаштування Firebase Cloud Messaging (FCM v1) та EAS Credentials

- Створення проєкту в **Firebase Console** та додавання Android-додатку з відповідним `package` (`com.modernchat.app` / `com.modernchat.app.dev`).
- Розміщення згенерованого файлу `google-services.json` у корінь проєкту та в папку `android/app/`.
- Генерація приватного ключа **Google Service Account (JSON)** у Firebase Console.
- Завантаження ключа до EAS через команду `eas credentials --platform android` (розділ _FCM V1 / Google Service Account Key_).

### 3. Бекенд Convex: збереження токенів та сервіс розсилки

- **Оновлення схеми `convex/schema.ts`:**
  - Додавання опціонального поля `pushToken: v.optional(v.string())` до таблиці `users`.
- **Мутація збереження токена `convex/users.ts`:**
  - Створення мутації `savePushToken`, яка оновлює `pushToken` для поточного авторизованого користувача.
- **Бекенд-сервіс `convex/pushNotifications.ts`:**
  - Реалізація внутрішніх екшенів (`internalAction`):
    - `sendPushNotification` — відправка одиничного сповіщення.
    - `sendPushNotificationsBatch` — відправка пачки сповіщень для учасників групового чату.
- **Диспетчеризація в `convex/messages.ts` (мутація `sendMessage`):**
  - Визначення отримувачів сповіщення:
    - Приватний діалог: інший співрозмовник.
    - Груповий чат: **усі** учасники бесіди, за винятком самого автора повідомлення.
  - Формування інформативного прев'ю повідомлення:
    - Текст: звичайний текстовий вміст.
    - Голосове: `🎤 Голосове повідомлення (Xс)`.
    - Відеокружечок: `📹 Відеоповідомлення (Xс)`.
    - Фотографія: `📷 Фотографія`.
  - Формування заголовка: для груп — `Назва групи • Ім'я автора`, для приватних — `Ім'я автора`.
  - Виклик екшену через планувальник: `ctx.scheduler.runAfter(0, internal.pushNotifications.send..., ...)`.

### 4. Клієнтський хук `usePushNotifications` та Deep Linking

- Створення хука `hooks/usePushNotifications.ts`.
- Глобальне налаштування `Notifications.setNotificationHandler` для показу банерів та відтворення звуку навіть у активному стані (Foreground).
- Налаштування Android Notification Channel з максимальною важливістю (`AndroidImportance.MAX`), звуком та вібрацією.
- Запит системних прав на пристрої (`requestPermissionsAsync`) та отримання `ExponentPushToken`.
- Автоматичне збереження токена в Convex при авторизації користувача.
- **Обробка переходів (Deep Linking):**
  - Обробка кліку у згорнутому/фоновому стані через `addNotificationResponseReceivedListener`.
  - Обробка кліку при **холодному старті (Cold Start)** через `useLastNotificationResponse` — коли додаток був повністю закритий, користувач тапає пуш, додаток завантажується та самостійно переходить у відкритий чат!
- Підключення хука в кореневому лейауті `components/InitialLayout.tsx` (або `app/_layout.tsx`).

### 5. Тестування та верифікація

- Перевірка отримання токена у Convex Dashboard (таблиця `users`).
- Тестове надсилання через офіційний вебінструмент [Expo Push Notification Tool](https://expo.dev/notifications).
- Перевірка надсилання реальних повідомлень між двома різними смартфонами або емулятором і реальним телефоном.

## 🏛️ Порівняння поведінки сповіщень у різних станах додатку

| Стан додатку                                              | Як приходить сповіщення                      | Що бачить користувач                                       | Поведінка при кліку (Deep Linking)                                               |
| :-------------------------------------------------------- | :------------------------------------------- | :--------------------------------------------------------- | :------------------------------------------------------------------------------- |
| **Foreground** _(Додаток відкритий)_                      | Обробляється через `setNotificationHandler`  | Спливаючий банер зверху екрана, системний звук та вібрація | Викликається `handleNotificationNavigation`, відкривається чат                   |
| **Background** _(Додаток згорнутий)_                      | Обробляється системною службою Android / FCM | Системне сповіщення у шторці з назвою чату та текстом      | Розгортає додаток і переходить за роутом `/chat/[id]`                            |
| **Killed / Cold Start** _(Додаток вивантажено з пам'яті)_ | Обробляється нативним сервісом ОС у фоні     | Системне сповіщення у шторці навіть при вимкненому екрані  | Запускає додаток з нуля, `useLastNotificationResponse` відкриває відповідний чат |

## 🌟 Бонусні завдання (За бажанням, для додаткових балів)

1. **Кастомний звук та вібраційний патерн для сповіщень:**
   - Налаштуйте в `Notifications.setNotificationChannelAsync` кастомний звук сповіщення (наприклад, фірмовий звук у стилі Telegram) та власний ритмічний патерн вібрації.
2. **Push-сповіщення для реакцій на повідомлення:**
   - Оновіть мутацію додавання емодзі-реакцій (`addReaction` / `toggleReaction`): коли співрозмовник ставить реакцію ❤️ / 🔥 / 👍 на повідомлення, автору повідомлення надходить пуш із текстом: `🔥 [Ім'я] відреагував(ла) на ваше повідомлення`.
3. **Очищення `pushToken` при виході з акаунта (Sign Out):**
   - Додайте мутацію `removePushToken`: коли користувач натискає «Вийти з акаунта», токен видаляється з його профілю в базі даних. Це запобігає надсиланню особистих повідомлень на пристрій, якщо з нього вийшов поточний користувач.
